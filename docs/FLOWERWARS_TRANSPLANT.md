# FlowerWars 구조·지휘 이식

현재 추가 이식: 초기 전투 즉시 시작 대신 **40명 예비 병력 배치 → 5분 준비/즉시 시작 → 전투 지휘** 흐름을 적용했습니다. 진형 카드를 선택해 아군 진영에10명씩 놓고, 자동 배치 또는 전투 시작 시 남은 병력을 배치합니다. 준비 중 전투 틱은 진행하지 않습니다. 하단 배치 카드와 지휘 모드 전환, 왼쪽 지휘관 목록, 오른쪽 하단5개 원형 명령, 접이식 진형창, 숨김 도구창으로 화면을 재구성했습니다. 배치 지역과 진형 미리보기도 표시합니다. 캐릭터/국가 설정과 고저차·엄폐·제압·포격·HQ 점령은 보존합니다.

검증: 전체 Node99개 통과; `tests/flow-browser.py`에서390×844와1280×800의 실제 배치·준비 중 시간 정지·진형 전환·전투 시작·접이식 지휘창·포격 통과(페이지 오류0).

기준: FlowerWars-MINI `0d4e7a513c6fe02ab864fb6335792bd9d2280312`.
서비스 게시 작업은 수행하지 않았습니다.

## 유지한 범위

H0/H1/H2, 경사로, 엄폐, 제압, 포격, 지휘소 점령, 고정40 대40 편성은 AshenFront 규칙을 유지합니다. 캐릭터 파츠·16개 조립 프로필·국가별 설정·총과 애니메이션·회색 팔레트 파일은 변경하지 않았습니다. FlowerWars의 PvP·서버·동기화·예비 병력 배치·깃발 파괴·치유/소환 병종은 넣지 않았습니다. 런타임 의존성을 추가하지 않았습니다.

## 이식 대응

| FlowerWars 참고 | AshenFront 적용 |
|---|---|
| `app`, `commander-portrait`, `gesture-commands` | `ui/roster`, `ui/selection`, `ui/controls`: 소대 접기, 소대 전체/복수 선택, 현재 캐릭터 초상, 길게 누르기, 더블 탭 시점 이동 |
| `squad-orders` | `sim/commands`, `sim/tactical-orders`: 원자적 명령 교체, 보이는 적 집중 공격, 단계적 우회와 후속 공격, 이동 중 재지정 |
| `formation-planner` | `sim/formations`, `sim/orders`: 횡대·종대·방진·산개, 진행축 회전, 이미 맞는 자리 유지, 도착 인원 표시 |
| `navigation` | 기존 예약·점유·경사로 엔진을 유지하며 넓은 진형의 정확한 목적지로 연결하는 거리장 전환과 캐시 정리 보강 |
| `command-overlay` | `render/command-overlay`: 선택 분대마다 실제 경유점·목적지·자리 표시, 명령 확인 피드백 |
| `ai/observer`, `planner`, `operations`, `commands` | `sim/ai/`: 지형 관측, 전술 선택, 역할·작전 유지, 진행/정체 추적, 중복 명령 방지와 공통 명령 게이트 |

명령·진형·AI는 화면 코드에서 분리했습니다. `engine.tick`은 명령 수신 → 전술 명령 갱신 → 기존 이동 → 사격 → 제압 회복 → 목표 갱신 → AI 순서로 실행합니다. CPU가 직접 위치를 바꾸거나 길찾기 예약을 우회하지 않습니다.

## 실제 동작

- 분대 선택 후 지점은 이동, 시야에 있는 적은 집중 공격입니다. 버튼으로 이동/공격/우회/포격을 명시적으로 선택할 수도 있습니다.
- 복수 이동은 목표 주변에 분대별 목적지를 분산합니다. 첫 분대는 지정 지점을 유지해 지휘소 점령 목적을 놓치지 않습니다.
- 우회는 좌우 위협을 비교해 측면 경유점을 정하고, 적을 지정했다면 접근 후 공격으로 이어집니다. 새 명령은 이전 경유와 후속 명령을 취소합니다.
- 공격 목표가 시야에서 사라지면 마지막 접근 위치까지만 탐색합니다. 숨은 적의 새 위치를 따라가지 않습니다.
- AI는 수비·전선·돌파·기동·지원 역할을 유지하고, 지형 관문을 이용합니다. 본진 위협·제압·정체에 대응하며 마지막 생존 수비대는 공격에 참여해 영구 대기를 피합니다.
- AI 지휘 상태는 `WeakMap`, UI용 역할 표시는 비열거 속성으로 관리합니다. 관측 간 숨은 적의 위치/체력을 다시 읽지 않는 회귀 검사가 있습니다.
- 터치 이동·핀치·길게 누르기는 단순 탭 명령과 분리합니다. 전장 포인터를 가리던 목록은 명령 선택 시 닫힙니다. 시야 갱신은 틱 나머지 대신 경과 틱을 사용해 프레임 건너뜀에서도 멈추지 않습니다.

## 성능과 한계

`node tools/transplant-benchmark.mjs`, Node24.19.0, 양팀 봇과 전투를 켜고 각각100틱을 측정했습니다. 브라우저 FPS나 실기기 측정이 아닙니다.

| 지도 / 전체 병력 | 평균 ms/틱 | p95 | 최대(초기 구축 포함) |
|---|---:|---:|---:|
|64×48 /80명 — 기본|0.90|1.63|22.09|
|128×96 /180명 — 개발용|1.25|2.47|19.48|
|256×192 /360명 — 개발용|3.07|5.76|58.70|

모든 표본에서 이동 탐색은2048 확장/틱 상한을 지켰습니다. 큰 지도 첫 지형 그래프 구축은 여전히 프레임 지연을 만들 수 있습니다. 큰 전장 렌더링·실제 휴대폰 성능 개선은 주장하지 않습니다.

우회 후보는 보이는 위협과 측면 경유점으로 선택합니다. 해당 경유점에 실제 통로가 없으면 기존 경로 실패 상태로 알리며, 임의로 반대편 우회를 강제하지 않습니다. 지형 그래프의 거리는 추정값이고 실제 이동은 기존 Navigation이 결정합니다. 모든 혼잡 배치의 완주를 보장하지 않습니다.
